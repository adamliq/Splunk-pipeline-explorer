Try an event, search-time order by app, and export

Three tools for the Config view. Try an event: paste one, or pick one from a package’s samples folder, and the source type map lights the transforms that match it, the source type it becomes and the extractions that give it fields, with each step listed in order. Search-time order: rank the search-time settings for a search in an app, by what each app’s metadata exports, as Splunk does, instead of one global order. Copy or export: a source type’s merged settings as .conf text, and its map as a PNG. Every target scene is the real explorer with the prototype applied to Build 223; each “Today” scene is Build 223, set up by the same steps. Five scenes use the Fortinet FortiGate Add-on for Splunk 1.6.10’s package, which isn’t in the repository; the order’s scenes use two made-up apps, one that keeps its settings to itself and one that exports them.

    The design in short

    Index time
    The TRANSFORMS- lines of the source type the event arrives as, with [default]’s, in ASCII order of their names, each line’s transforms in the order it lists them. Every transform runs, whatever an earlier one did: one can send the event to nullQueue and a later one send it back.
    Search time
    The source type it becomes: EXTRACT-, REPORT-, KV_MODE, then FIELDALIAS-, as Splunk orders them. EVAL- and LOOKUP- lines are counted, not run.
    Expressions
    Splunk’s PCRE is translated to JavaScript’s dialect; what can’t be is reported, not guessed.
    Lit
    A line that gave the event something is outlined, one tried that gave nothing is dimmed, and the card of what the event becomes is outlined. Follow opens that source type’s map, lit the same way.
    Order
    The search-time lines of props.conf and transforms.conf, and every line of eventtypes.conf and tags.conf, ranked for a search in the app chosen. Index-time lines keep the global order.
    Sharing
    Another app’s line counts only where its metadata exports it (export = system), local.meta before default.meta, the most specific stanza first. A line not shared has no effect, and says why.
    Copy
    .conf text: the inputs that name the source type, its props.conf stanza and the transforms its lines name, each line under the file it comes from, overridden lines left out.
    Image
    The map as plain SVG, drawn into a PNG at twice its size: its title, summary, columns and lines, without the controls.
    Unchanged
    With the global order and nothing tried, every view, the panel and every map are as in Build 223, but for the picker and the tools.

    What Copy settings gives

    For acme:fw, from the made-up apps, in the global order. Save settings saves the same text as acme_fw.conf.

    # acme:fw: its settings as Splunk merges them, from Splunk Pipeline Explorer.
# Every setting in the global order. Overridden lines are left out.

# props.conf
[acme:fw]
# A_site/local/props.conf
EXTRACT-src = src=(?<src>\S+)
FIELDALIAS-site = src AS site_src
# Splunk_TA_try/default/props.conf
EXTRACT-port = (?P<dest_port>\d+)/tcp
EXTRACT-user = user=(?<user>\w+) in raw_user
EXTRACT-odd = (?i)x(?-i)y
REPORT-kv = acme_kv
REPORT-fmt = acme_fmt
FIELDALIAS-a = src AS src_ip dest_port AS port
FIELDALIAS-b = nosuch AS other
EVAL-risk = if(port==443,"low","high")
KV_MODE = none

# transforms.conf
[acme_kv]
# Splunk_TA_try/default/transforms.conf
DELIMS = " ", ":"

[acme_fmt]
# Splunk_TA_try/default/transforms.conf
REGEX = (\w+)@(\w+)
FORMAT = $1::$2
