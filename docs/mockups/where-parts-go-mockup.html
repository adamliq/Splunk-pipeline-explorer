    Where the placements come from

    Lines
    Where each takes effect, as Build 221 counts them. Splunk puts each setting on the first component that handles its phase: inputs where data is read, parsing on a heavy forwarder or an indexer, search-time settings on a search head.
    Settings files
    The ones the Config view doesn’t read line by line go where the packaging toolkit’s @placement notes put any of their settings. A file with no notes, like outputs.conf, is kept on every tier.
    Folders
    lookups, static, appserver and default/data on search heads. app.conf and metadata on every tier. A script goes where what names it runs.
    app.manifest
    Its targetWorkloads, as the toolkit reads them: none named, or *, is every workload, and a name it doesn’t know, it rejects.

    The page beside the toolkit

    62 settings
    Of the Fortinet add-on and a made-up set: 50 take effect where the toolkit puts them.
    5 input settings
    NO_BINARY_CHECK, CHECK_METHOD, INDEXED_EXTRACTIONS, TIMESTAMP_FIELDS and FIELD_NAMES act wherever the data is read. The toolkit puts them on forwarders only.
    7 transform settings
    An index-time transform’s REGEX, FORMAT, DEST_KEY and SOURCE_KEY act on a heavy forwarder too. The toolkit puts transforms.conf on search heads and indexers. The page keeps Build 221’s tiers for lines.
