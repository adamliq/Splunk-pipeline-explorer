Lookups and calculated fields in Try an event

Try an event now runs the rest of a source type’s search-time settings. Its calculated fields (EVAL-) are evaluated by a small eval engine, all from the same fields, as Splunk runs them “as if in parallel”. Its lookups (LOOKUP-) run on the lookup files the page reads, in order, none on another’s output. At index time, INGEST_EVAL sets the index, the queue and indexed fields. What the engine can’t compute, or Splunk’s docs don’t define, is said on the step, not guessed. Every target scene is the real explorer with the prototype applied to Build 224; each “Today” scene is Build 224, set up by the same steps. Four scenes use the Fortinet FortiGate Add-on for Splunk 1.6.10’s package, which isn’t in the repository; the others use a made-up app that covers the rules the add-on doesn’t use.

    The design in short

    Order
    Extractions, aliases, then calculated fields, then lookups, as props.conf orders them. Each calculated field sees the fields as they were after the aliases; each lookup, as they were after the calculated fields.
    Values
    A field’s value is a number where it reads as one, and keeps its own text; + adds numbers and joins text; a missing value gives no value.
    OUTPUT
    Writes over the event’s fields, and clears them when no row matches. OUTPUTNEW writes only fields the event doesn’t have.
    Matching
    Exact and case sensitive unless case_sensitive_match = false; WILDCARD() and CIDR() as match_type says; up to max_matches rows, 100 unless set; min_matches with default_match.
    Not run
    KV store, external and time-based lookups, a file not read, and functions outside the engine’s list: each step says so.
    On the map
    A line that gives something is lit, one that gives nothing dimmed, one not run left as it is.

    What Splunk’s docs leave open

    Missing values
    What arithmetic or a comparison gives with a missing field: here, no value, which a condition takes as false.
    A number + text
    The docs define + for two numbers or two strings: anything else isn’t computed, and the step says why.
    CSV spaces
    Whether spaces round a lookup file’s names and values are kept: here they are left out, and the step says “to check”.
    INGEST_EVAL keys
    Its examples set index, queue and new fields; host, source and sourcetype are read, not set.
