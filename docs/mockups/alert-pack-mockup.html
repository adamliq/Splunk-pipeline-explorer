Alert and dashboard pack

A Splunk app of scheduled alerts and a dashboard, written for the topology in the Builder: deployment clients that stop phoning home, app installs that fail, versions that drift, and queues that stay full. Downloaded from the page, installed in Splunk 10.6.1.1, and run against each condition made real.

    Where the design comes from

    What Splunk records
    The Deployment Server’s own indexes, _dsphonehome, _dsclient and _dsappevent, and metrics.log and splunkd.log in _internal. The stale and failed alerts follow Agent Management’s own searches; the stale threshold uses the interval the topology sets, not an average.
    Tested in Splunk
    A Deployment Server and two clients on Splunk 10.6.1.1: a client stopped, an install that can’t unpack, an app changed while a client was away, a forwarder cut off from its indexers. Each alert found its condition and nothing else.
    Nothing leaves the page
    The app is written and packed in the tab; the page keeps nothing.
