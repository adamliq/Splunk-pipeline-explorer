Parsing laboratory: more examples, two boundaries

Operate › Parsing laboratory gets ten more examples, in two groups: five more samples of common formats, and five common mistakes. Two event boundaries come with them, CSV header line and Fixed length, and so does KV_MODE = multi. Each example says what it shows, sets every setting it depends on, and adds the props lines its format needs to the generated configuration. A 1 MB input lists its first 25 events and counts all of them. Every scene is the real laboratory with the prototype block appended to Build 199; the “Today” scene is Build 199 as shipped.

    The rules in short

    Two groups
    Samples: formats as they should be parsed. Common mistakes: a sample with one setting wrong.
    Choosing one
    Every setting comes from the example, starting from the laboratory’s defaults (TRUNCATE 10000, record length 128, UTC, index security, route result=failure → security_alerts). The index-time processing tier is kept.
    The note
    One line on what the example shows, and the props lines its format needs. Change a setting and it reads “Custom settings”. Editing the raw input keeps the example.
    CSV header line
    A new event boundary: an event starts at each line that repeats the input’s first line. The lines are trimmed, as with the other boundaries.
    Fixed length
    A new event boundary: an event ends after every N characters, N from Record length (16 or more). Every character is kept. After a line break the count starts again, as .{N} does in Splunk, and a record of another length gets a warning.
    Merging
    Off and disabled with both new boundaries: LINE_BREAKER alone ends each event.
    KV_MODE = multi
    Each event is read as a table: the first line names the columns, each later line is a row, shown as Row 1, Row 2. Columns split on commas when the first line has them, otherwise on spaces.
    Large input
    The first 25 events are listed, under a note; the metrics count all of them. Download results has every event. The evidence pack and the architecture report list the first 25, with the full counts.
    Configuration
    The new boundaries write their own lines (SHOULD_LINEMERGE, LINE_BREAKER, LINE_BREAKER_LOOKBEHIND, TIME_PREFIX) from the settings, so the lines stay when the settings become custom. While its settings are unchanged, an example’s own lines go in too.
    Walkthrough
    Open in walkthrough picks the walkthrough’s JSON, CSV, Windows or syslog sample from the settings, so the JSON examples open as JSON. The new boundaries open as syslog.
    Also fixed
    A long event scrolls inside its card, 20 lines at a time. The merge checkbox sits beside its label.

    What Download config writes for the new boundaries

    Fixed-length records

    [badge:controller]
SHOULD_LINEMERGE = false
# Fixed-length records: end an event after every 128 characters. The empty group keeps every character.
LINE_BREAKER = .{128}()
# Look back at least one record, so a record split between read chunks is counted from its start.
LINE_BREAKER_LOOKBEHIND = 128
# On a universal forwarder that reads this file, break at the same points so each record reaches an indexer whole:
# EVENT_BREAKER_ENABLE = true
# EVENT_BREAKER = .{128}()
TRUNCATE = 10000
MAX_TIMESTAMP_LOOKAHEAD = 20
TIME_FORMAT = %Y-%m-%dT%H:%M:%S%Z
TZ = UTC
# Index-time structured extraction
INDEXED_EXTRACTIONS = none
# Search-time field extraction
KV_MODE = auto

    CSV header per event

    [vpn:health:csv]
SHOULD_LINEMERGE = false
# Start an event at each header line.
LINE_BREAKER = ([\r\n]+)(?=collected,host,cpu_pct,mem_pct,disk_pct)
TRUNCATE = 10000
# The header line comes first: read the time from the first row.
TIME_PREFIX = ^[^\r\n]*[\r\n]+
TIME_FORMAT = %Y-%m-%dT%H:%M:%S%Z
TZ = UTC
# Index-time structured extraction
INDEXED_EXTRACTIONS = none
# Search-time field extraction
# KV_MODE = multi reads each event as a table: the first line names the columns, and each later line is a row.
# Check on a test instance that the columns split on the commas.
KV_MODE = multi
