Ports on a load balancer and a Syslog Server

In the Builder, a Syslog Server now listens on as many ports as a design needs: UDP, TCP or TLS, any number from 1 to 65535, with the senders a port is for when it is theirs alone. A load balancer keeps its preset listeners and takes any other port too. Each link into either is checked against its receiver’s ports, and a load balancer’s listeners against its Syslog Servers’.

    Where the design comes from

    Dedicated ports
    SC4S, Splunk Connect for Syslog, gives a source technology a listening port of its own when its events can’t be told apart from others’, or it sends to a port other than UDP 514. It discourages using a default port as a dedicated one.
    TLS
    SC4S listens for TLS on 6514 when that is enabled. TLS runs over TCP, so TCP and TLS can’t share a port number; UDP can share one with either.
    Listeners
    A load balancer’s listener checks for connection requests using the protocol and port configured for it, on ports 1 to 65535, as AWS’s Network Load Balancer describes it. The Builder sends each listener to the same port on its members.
