Lookup checks in the Config view

The Config view reads the lookup files an app keeps in its lookups folder, from app packages, folders and .csv files picked on their own. For each lookup transforms.conf defines with a filename, it says whether that file is there, with its rows and columns; for each LOOKUP- line, whether the fields it names are columns of the lookup’s file, or of its fields_list. Build 222 drops the lookups folder, so it can say neither. Every target scene is the real explorer with the prototype applied to Build 222; each “Today” scene is Build 222, set up by the same steps. Four scenes use the Fortinet FortiGate Add-on for Splunk 1.6.10’s package, which isn’t in the repository: two of its four lookup files write their column names with a space after each comma.

    The design in short

    Files
    A .csv or .csv.gz in a lookups folder, or picked on its own. Its header gives its columns, as written; its rows are counted, up to 20 MB.
    Whose
    A lookup’s file is looked for in its own app’s lookups folder, then among files picked on their own, then in another app’s. An app read whole, from a package or a folder, is known to lack a file it doesn’t have.
    Fields
    A LOOKUP- line’s fields are found among the columns as written; only once the spaces round a name are left out; in another case; or not at all, with the nearest. A KV store or external lookup is checked against its fields_list, and match_type and time_field too.
    Spaces
    Whether Splunk keeps the spaces round a column’s name isn’t settled here: the line is to check, with the search that shows it.
    Panel
    Notes on the LOOKUP-, filename, match_type and time_field lines; a problem puts the line among those to check. A lookups tab lists the files.
    Unchanged
    With no lookup file read, and no app read whole, every view, the panel and every map are as in Build 222.
