Source type splits and Ingest Processor pipelines in the source type map

Build 217’s source type map, tested with the Fortinet FortiGate Add-on for Splunk 1.6.10. The add-on splits fortigate_log, and fgt_log, into four source types with one transform, and renames its older source types at search time. Build 217 draws each source type but not the split: faults 47 to 49. The fix follows it. The map also gains the Ingest Processor, only where an uploaded pipeline takes the source type. Every target scene is the real explorer with the prototype applied to Build 217 and the add-on’s props.conf and transforms.conf loaded, two of them with a pipeline’s SPL2 file as well; the “Today” scenes are Build 217 as shipped.

    The fix in short

    Names
    FORMAT, with each $n replaced by each word the REGEX’s nth group lists. Where a group lists no words, one destination says the name comes from the event, and names the source types in the files that fit.
    Splitting
    “Becomes fortigate_traffic”: which word the transform finds for it, “Follow”, and a line from the transform.
    Named
    The transform’s card under Read: “Events of fortigate_log and fgt_log become fortigate_traffic here, after they are parsed.”
    No effect
    When only a transform names a source type, its settings under Read, its parsing lines and its own TRANSFORMS-, RULESET- and SEDCMD- lines are faded, each card saying why.
    Renames
    A rename line leads to the source type it names, and that source type shows the stanzas searched under its name.
    Pipelines
    A .spl2 file goes in with the others. A pipeline is a statement that starts with from $source; its first where says which source types it takes.
    Sixth column
    “Ingest Processor”, after Transform, only where a pipeline takes the chosen source type: its commands in order, each with a line to what it leads to.
    Unchanged
    The example’s maps, which have no pipeline; the view’s Matrix.
