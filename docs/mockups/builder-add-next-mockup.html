Builder: add the next component from a handle

Click a card’s Event data handle and a list opens: the components that card can send event data to, each with the protocol its link will carry. Choose one and it is added after the card, already connected, in one step. The connection the handle starts is still there, so clicking another card’s handle connects the two as before. Testing found three faults in reaching the handles on Build 203; the same block fixes them. Every scene is the real Builder with the prototype block appended to Build 203; the “Today” scenes are Build 203 as shipped.

    The rules in short

    Opens
    Click a card’s Event data handle, or Tab to it and press Enter. The connection starts as before; the list opens beside it.
    Offers
    What the Builder’s live check lets the card send to, in the palette’s order. Not Splunk Cloud indexing after a Syslog Source, which validation rejects.
    Adds
    The component on its own, then connected exactly as the handles connect two cards. Selected and focused; one history step; the status line says what was added and how it connects.
    Where
    Auto, horizontal and vertical layouts place it as any card after another. In Free place: one column after the sender, level with it, or the first free place below.
    Closes
    Esc, or the active handle clicked again: closes and cancels. Another card’s Event data handle: connects. A click elsewhere: closes, the connection stays pending.
    Handles
    A strip bridges the 5 px gap above them. The card under the pointer, whose handle has keyboard focus, or that a connection starts from, comes to the front.
    Palette
    “Compatible next component” lists and adds the same way.
    Unchanged
    Fleet and Access handles, a Search Head’s handle, phones, Focus canvas and every other view.
