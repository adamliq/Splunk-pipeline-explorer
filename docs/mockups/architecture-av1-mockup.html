Purpose

The front page of the architecture pack: what the architecture covers, why it was described, what the views found, and where to read each view. Twelve issues recur across the views; each is listed once here with the views that show it.

Scope

  • Security telemetry collection, indexing, search, detection and response on Splunk Enterprise.
  • Sydney and Melbourne sites, Windows estate, AWS ap-southeast-2 workloads, cloud identity and SOAR.
  • 17 systems and 17 interfaces in the Builder reference topology.

Purpose and decisions supported

  • Decide what to build in each of three increments (Oct 2026 – Dec 2027).
  • Show accreditation evidence for data handling and system monitoring (ISM, Privacy Act).
  • Give each team its responsibilities and the gaps it owns.

How the pack was made

  • Generated from the Splunk Pipeline Explorer Builder topology (Build 167).
  • Views marked "example" carry illustrative values; replace them before use.
  • Status: draft. Architect and owners not yet named in most views.

Cross-cutting issues

Each issue appears in several views. Fixing it closes findings in every view listed. Ordered by severity, then by how many views it touches.

Views in the pack

Links open the published mockup. "Generated" means the Builder already produces the view; "Handoff" means a build specification is written.

Assumptions

  • The reference topology reflects the intended production design.
  • One indexer and one search head until Increment 3.
  • Volumes and targets are examples until measured.

Constraints

  • Australian Government ISM and Privacy Act 1988 apply (.gov.au estate).
  • Licence entitlement 180 GB/day today.
  • Network changes run in a weekly window.

Not yet described

  • AV-1 recommends next: StdV-2 (standards forecast), CV-3 (capability phasing), PV-2 (project timelines).
  • SvcV views are covered by SV views for this platform.
