Components that share a host

A host box groups the roles that run on one Splunk instance. Each role keeps its own card, inspector and connectors, so data lines leave the Heavy Forwarder and phone-home lines leave the Deployment Server. Collapse a host to fold it into one combined card.

Which roles can share a host

Roles on one hostResultWhy
Heavy Forwarder + Deployment ServerOKCommon in small estates. Warn above 50 deployment clients; move the DS to its own host.
License Manager + Monitoring ConsoleOKBoth light, both management plane.
Deployment Server + License ManagerOKWarn above 50 deployment clients.
Syslog Server + Universal ForwarderOKThe usual pattern; the file handoff is drawn as a local link.
Deployment Server + Indexer or cluster peerFlagConfiguration pushes compete with indexing; peers are managed by the cluster manager.
Monitoring Console + search head cluster memberFlagNot supported on SHC members.
Cluster manager + one of its peersFlagLosing the host loses both the manager and a copy.
Two roles listening on the same portFlagFor example two receivers on 9997 or two HEC inputs on 8088.
Any roles over the host's sizeWarnPipeline sets and ingest add up per host.

Where the host shows up

  1. Inventory: a Host column; roles on the same host share a row group.
  2. Architecture pack: "2 roles on splunk-hf01" in the component table and the deployment section.
  3. OV-1: one card with both icons, "Heavy Forwarder + Deployment Server".
  4. OV-2 / OV-3: roles stay in their own operational nodes; Realised by says "on shared host splunk-hf01".
  5. Topology file: each component carries hostId; hosts carry name, region and size. Re-import keeps them.
