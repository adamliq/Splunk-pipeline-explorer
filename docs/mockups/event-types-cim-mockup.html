Event types, tags and CIM data models in the Config view

The Config view reads an app’s eventtypes.conf and tags.conf, and the source type map follows a source type on to the Common Information Model: fortigate_traffic → [ftnt_fortigate_traffic] → network, communicate → Network Traffic. Each event type’s search is read for the source types it takes and the conditions it adds; tags.conf gives event types and field values their tags; and the CIM’s data models take the events whose tags their datasets require, as the CIM 8.8 documentation lists them. Build 221 reads neither file as what it is. Every target scene is the real explorer with the prototype applied to Build 221 (Build 220 with the Config view handoff); each “Today” scene is Build 221, set up by the same steps. Six scenes use the four configuration files of the Fortinet FortiGate Add-on for Splunk 1.6.10, which aren’t in the repository.

    The design in short

    Searches
    An event type’s search is read as the search command reads it: brackets, then NOT, then OR, then AND, which is implied between terms. Its sourcetype terms are decided for each source type, by the name a search sees; what is left is the condition it adds, shown as written. eventtype= terms are followed.
    Tags
    [eventtype=…] stanzas tag an event type’s events; [sourcetype=…] stanzas tag every event of a source type; any other [field=value] tags the events that have that value.
    Data models
    A data model takes an event when its tags complete one of the model’s root datasets. Every event’s tags count, with those of one event type or tag stanza that takes only some events. The datasets reached are listed.
    Panel
    Tabs E and #. Stage 116 or 117 for each stanza, its settings acting with it. Each stanza’s line says which events it takes, its tags and the data models they fit. Disabled event types, searches with a pipe, mistyped settings and tags of missing event types are flagged.
    Map
    The Search column’s last card lists the event types, each with its condition and tags; ones with no tags fold when there are more than three. The Data models column has a card for each data model, level with the first row that feeds it, with a line from each.
    Unchanged
    Without these files, every view, the panel and every map are as in Build 221.
