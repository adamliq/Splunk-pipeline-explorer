Event types, tags and every sample

Try an event no longer stops at the lookups. It ends with the event types the event gets, their tags and the CIM data models it lands in, each matched as Splunk 10.6.1.1 matched them. And the samples, or the lines pasted in the box, can be tried all at once: what they’re indexed as, the event types, tags and data models they get, each line with the events it gives something to, and each field with the events that have it. The Fortinet add-on’s 54 samples get exactly Splunk’s event types and tags.

    Checked in Splunk

    Fortinet
    The add-on’s 54 samples, as Splunk indexed and searched them: each one’s event types and tags, the same on the page, with none left open.
    Every rule
    A made-up app’s event against 52 event types, one for each rule: 49 as Splunk matched them, none otherwise, and the two that ask for host and index left open. Its ten tags, Splunk’s.
    Its own fields
    An event whose text has eventtype= and tag=: event types replace the one, and an event that gets none keeps it; tags replace the other.
    Evidence
    docs/splunk-checks.md, its event types section: each rule, and each of the 52 searches with Splunk’s answer and the page’s.

    The rules in short

    Values
    In any case, with * as a wildcard; a range like 10.0.0.0/8 takes its addresses; two numbers compare as numbers. Any of a field’s values can match.
    Not
    field!=x needs the field, and none of its values x. NOT field=x is also true with no field.
    Free text
    The term’s pieces, split where Splunk splits the event, one after another: 1.2 is in 10.1.2.3, ab isn’t in abc.
    Names
    Field names are case sensitive. sourcetype is the name the event is searched as. host, source and index are known only once a transform sets them.
    Tags
    [field=value] tags a value written exactly so; [eventtype=x] tags x’s events. A disabled event type or tag gives nothing.
