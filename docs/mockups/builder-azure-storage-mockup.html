Ingest Processor → Azure Blob Storage

Ingest Processor can write routed events to an Azure Blob Storage or Azure Data Lake Storage container. In Splunk Cloud you create a Microsoft Azure connection (a Microsoft Entra app registration) and a dataset for the container in the Data Management app, then use the dataset as a pipeline destination. The dataset can also be searchable by federated search. The Builder models the same parts: an Azure Storage Dataset, a Microsoft Azure Connection, and the data link from Ingest Processor or Edge Processor. Pick a scene, then select a card or the link label.

    Links

    Only a processor writes to a dataset. The connection and the search tier belong to the authentication and search paths, so they have no data handle.

    FromToResultProtocol and portMessage when refused
    Ingest ProcessorAzure Storage DatasetAllowedHTTPS 443 to <account>.blob.core.windows.net (Data Lake: .dfs.), TLS Required, Microsoft Entra app—
    Edge ProcessorAzure Storage DatasetAllowedThe same, from the customer network—
    Any other componentAzure Storage DatasetRefused—Only an Ingest Processor or Edge Processor can write to an Azure Storage Dataset.
    Azure Storage DatasetAnythingRefused—An Azure Storage Dataset is a destination. It doesn't send events.
    AnythingMicrosoft Azure Connection, or the other wayRefused—Connections, catalogs and Cloud Search belong to the authentication and search paths. They don't carry events.
    Ingest ProcessorAzure dataset set to Federated search onlyNot offered—Azure datasets are routing destinations, so there is no search-only use.
    • Versions. Ingest Processor writes to Azure need Splunk Cloud Platform 10.5.2605 or higher (general availability, 29 June 2026), in any region, without Federated Search. The controlled-availability release needed 10.4.2604 or higher and Federated Search.
    • The secret stays in Splunk Cloud. The connection records the directory (tenant) ID and application (client) ID only. Creating it needs the edit_datasets and admin_all_objects capabilities.
    • Reaching the account. Ingest Processor runs in Splunk Cloud, so it reaches the storage account's public endpoint. With "Selected networks", the storage firewall must allow Splunk Cloud. "Private endpoint only" needs private connectivity confirmed with Splunk.
    • Amazon S3 datasets, fixed at the same time: their links read port 8089 because the protocol text mentions "Data Management". Object writes use HTTPS 443.

    What the views show

    The dataset is a system in its own right, owned by the cloud storage team, like the Amazon S3 Dataset. The connection is part of the authentication path, so views about events don't show it.

    ViewWith an Azure Storage Dataset
    CanvasA data link from the processor. The connection and Cloud Search sit apart. A guide above the canvas, next to the S3 one, lists the write and search paths. Group by tier puts the dataset in Indexing with the S3 datasets, and the connection in management.
