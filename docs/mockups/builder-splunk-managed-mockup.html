Splunk-managed components

Splunk Cloud Search, Ingest Processor and Splunk SOAR · Cloud get the same managed treatment as Splunk Cloud indexing: a managed card, the Splunk Cloud provider as owner, their own Splunk Cloud security zone, and no customer host or management roles. A stack can also have a second managed search head, the ES search head: a premium search head for Enterprise Security, licensed as ES Premier, which includes UEBA and SOAR. Splunk Cloud ES search head

Splunk Cloud runs Enterprise Security on its own premium search head on the stack, next to Splunk Cloud Search. Splunk manages it like the other stack services. Its licence edition decides what it includes; Premier is the default.

IncludedES Premier (default)ES Essentials
Enterprise SecurityYes: detections, risk-based alerting, findings and investigationsYes
UEBAYes, on by default. It needs asset and identity dataNo. UEBA is Premier only
SOARYes: actions and playbooks run from ES once it's paired with a Splunk SOAR tenantNo
  • Search link: Splunk Cloud indexing → ES search head on the same stack, labelled "Splunk Cloud search". Nothing else can send to it.
  • Findings link: ES search head → Splunk SOAR (Cloud or on-premises). This is the ES–SOAR pairing over HTTPS 443, with the allow lists recorded. SOAR still has no event-data parent.
  • Sign-in: users and identity providers can sign in to it with SAML.
  • Views: S12 Correlation and risk is deployed, and SF-09, SF-10 and SF-11 can be In place. CV-1 C5 and CV-2 C5.1 and C5.2 are no longer Planned. A new UEBA part (C5.3, S12.3) is realised with Premier.
  • OV-2: it joins "Search and detection (Splunk Cloud)" with Splunk Cloud Search.
  • New rules: PR-CLOUD-19 (it has a search link), PR-CLOUD-20 (Premier is paired with SOAR) and PR-CLOUD-21 (UEBA has asset and identity data).

Review and threat model

  • Threat model: a "Splunk Cloud (provider managed)" zone holds the managed services, plus the configuration hosted in them. Threats on the managed services are transferred to the Splunk Cloud provider.
  • Flows into them stay yours: the transport from your forwarders and collectors is still your control.
  • Inventory and pack: hosting reads "Splunk Cloud · acme" or "Splunk SOAR Cloud · acmesec". The pack's deployment section lists every managed service.
  • PR-CLOUD-12 widens to every managed component: no customer management roles, no shared customer host.
  • PR-CLOUD-17 (new): a self-managed Search Head that searches Splunk Cloud indexing gets a warning in the Splunk Cloud profile. Use Splunk Cloud Search instead.
  • AR-008 and PR-HYB-01/02 recognise managed components: the stack region counts as placement, and the managed boundary counts as the cloud boundary without a Cloud tenant group.
