The Config view: your .conf files on the Matrix

A new Config view maps every line of uploaded inputs.conf, props.conf and transforms.conf files to the Matrix stage that applies it. Files of one kind merge in Splunk’s precedence order. The component strip says which component the lines are checked against, and gains a Search Head, whose search-time settings get ten stages of their own. Every scene is the real explorer with the prototype block appended to Build 204; the “Today” scene is Build 204 as shipped.

    The rules in short

    View
    Config, beside Matrix: the compact component strip, the files panel and the view’s own Matrix. The Matrix view is unchanged but for the Search Head column and the search-time stages.
    Files
    inputs.conf, props.conf and transforms.conf, as files or folders, picked or dropped. Each is told apart by its name, or by what is in it.
    Precedence
    Files of a kind merge as Splunk merges them: system/local, then every app’s local, then every app’s default, then system/default; apps in ASCII order. On an indexer cluster peer, peer-apps local comes first, and peer-apps default before the other apps’ default. A folder’s paths give each file its place; a file on its own gets a place you set. etc/users and the folders Splunk sends to other instances are left out, and named.
    Read together
    TRANSFORMS-, REPORT- and LOOKUP- find their transforms.conf stanzas; a monitor finds its [source::] stanza; a sourcetype finds its props.conf stanza.
    Checked against
    The component chosen in the strip. Settings read with the source act on a Heavy Forwarder, indexer or search head only for data it reads itself. An input’s settings act only where the input does. Search peers use the search head’s copy of search-time settings.
    Flagged
    Typos, settings in the wrong file, DEST_KEY in the wrong case, a stanza props.conf names that transforms.conf lacks, a transform nothing runs, a disabled input, a setting a file sets twice.
    Secrets
    Tokens and passwords show their last four characters.
    Not kept
    The files stay in the page and are gone on reload.
